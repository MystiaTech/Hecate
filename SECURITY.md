# Security policy

## Reporting a vulnerability

Do not open a public issue with exploit details, secrets, household data, or
personal information. Use GitHub's private vulnerability reporting feature when
available. If that channel is unavailable, contact the repository owner through
their published GitHub contact method and share only the minimum necessary
information.

The maintainer will acknowledge, triage, coordinate remediation, record any
time-bounded exception, and plan rollback or disclosure as appropriate. No
response-time guarantee is made while the project is pre-implementation.

## Supported versions and limits

No production release is currently supported. Support and deprecation windows
must be declared with a release; security fixes target supported releases and
`Dev`. Branch protection, dependency alerts, code scanning, secret scanning,
and human review reduce risk but cannot prevent every malicious or mistaken
change. Administrator bypass may exist.

CodeRabbit or another external review service is not installed. Such a service
would require separate approval because it receives access to pull-request code.
